## Defect found in review, and fixed

The Done-when clause requiring a superseded packet to be distinguishable was met in the
export and **not** in the browse view.

`0004-E03-T02` is superseded by `0004-E03-T03`. The live export carries that correctly:

```
status: "not started"   taken_by: null   superseded_by: "0004-E03-T03"
```

Supersession is deliberately not a `Status` — a packet keeps the status it held when it
was replaced — so `summarize()` in `surface/view.go` computed
`Unclaimed = status == "not started" && TakenBy == nil` and dropped `superseded_by`
entirely. The list view therefore advertised a retired packet as available work, while the
detail view was correct. That is the hazard `check-packet-index.sh` prevents in the
repository, reintroduced through the app — and it matters because E04's premise is that
sessions take work from the app rather than from `packets/`.

`PacketSummary` now carries `superseded_by`, and supersession disqualifies a packet from
`unclaimed` regardless of status. `TestSupersededPacketIsNotOfferedAsWork` covers both
directions: a superseded packet is not offered, and an ordinary `not started` packet still
is. Neutralising the guard fails it on the assertion, not on compilation:

```
--- FAIL: TestSupersededPacketIsNotOfferedAsWork
    summary_test.go:19: a superseded packet is offered as unclaimed work
```

15 packages pass with the fix in place.
