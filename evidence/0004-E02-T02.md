## Decisions and adjustments

E01's packet model was not changed. Editable drafts live in an application-layer workspace.
Issue passes the body once to E01's `Tracker.Issue`; replacement issue passes it to the
existing atomic `Tracker.Supersede`. E01 remains the only owner of issued bodies, history,
links, closure, and optimistic packet versions.

T01's complete built route list was GET-only because that packet was read-only. T02 requires
writes, so the implementation preserves the real read routes and replaces the global
GET-only assertion with an exact route inventory plus a four-route draft lifecycle allowlist.
There is still no route, form, or API operation that changes an issued body's Goal, Boundary,
Done-when, Check, or Context.

Initiative and epic are selected from the tenant-filtered held packet export. The target is
the packet's real repository, `work-tracker`, from the service's explicit target catalog.
Tenant comes only from the verified identity principal and is revalidated against the held
published directory at issue. The issue actor comes only from the signed subject.

## What the app cannot yet do that a file can

- Drafts and newly appended events are process memory only. A restart or a second instance
  does not recover or coordinate them, while a committed file is durable and reviewable.
- Issue does not yet persist an event store or publish a new packet export. Therefore a new
  packet is recoverable through the authored-packet API only for the lifetime of that process;
  it does not appear in T01's held initiative list or become available to sessions.
- Supersession can currently target packets issued by this process. It cannot import and
  supersede a packet that exists only in the held export without guessing E01 event history.
- Initiative/epic validation uses the presence of an existing tenant packet. The app cannot
  author the first packet for a brand-new initiative or epic because no separate initiative
  catalog contract exists.
- The app target catalog currently contains only `work-tracker`; a file can name another
  repository pending that repository's own validation workflow.
- Draft saves keep only the current optimistic version. Unlike version control, they do not
  retain a human-readable diff of every pre-issue edit.
- Identity supplies subject and tenant but no chief-of-staff role claim. This packet provided
  no role contract, so the app cannot distinguish that role from another signed human in the
  same tenant.
