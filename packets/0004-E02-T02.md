## Context

The Founder's third requirement: **the chief-of-staff creates task packets in the app.**

This is the first write path in the product, and it is where the freeze is most easily lost.
Writing a packet and editing one look almost identical in an interface. They are not: a packet
whose Goal changes after issue means a session executed something nobody can reconstruct.

**Issue is the moment scope freezes.** Before it, a draft is freely editable. After it,
nothing edits — a wrong packet is superseded by a new one naming its parent.

**Dependency, stated honestly:** this packet's Check names routes and model operations from
T01 and E01 that may differ from what was actually built. Adjust to what is real and say what
you changed.

## Goal

A packet is composed, issued and — when it turns out wrong — superseded, entirely in the app,
with its scope frozen at issue and its original always recoverable.

## Boundary

**Authoring only.** No session API, no agent write-back, no migration of `packets/`.

**No route may edit an issued packet's body.** Not "guarded", not "admin-only" — the route
must not exist. If a requirement seems to need one, stop and say so.

Do not change E01's model to make the interface easier. If the model is wrong, report it.

## Done when

- A draft packet is composed with all its fields, and **is freely editable while a draft**.
- **Issue freezes the body.** After issue, no route, form, or API mutates Goal, Boundary,
  Done-when, Check or Context. Asserted mechanically against the built routes.
- **Supersession is available and linked both ways.** The new packet names its parent; the
  parent closes as superseded; the original body renders unchanged.
- A packet is issued against a real initiative, epic, target and **tenant validated against
  the published directory**.
- The author is recorded on the issue event and rendered in the history.
- **A draft cannot be issued incomplete** — a packet with no Check is not a packet.
- Every rule has a test that fails when the rule is removed.

## Check

```bash
go test ./... && go vet ./...
npm ci && npm test && npm run build
```

Then demonstrate:

1. Compose a draft, **edit it several times**, issue it.
2. **Attempt to change its Goal after issue** by every route the app exposes. Show each
   refused, and show the route inventory proves no such route exists.
3. Supersede it. **Show the original body unchanged**, both links, and the parent closed as
   superseded.
4. **Attempt to issue a draft with no Check.** Refused.
5. Issue against an unknown tenant. Refused.
6. Delete the freeze check from the implementation and show the mutation gate reports a new
   survivor. Restore it.

## Notes

The awkwardness of supersede-over-edit is deliberate and is doing work. **Do not add an edit
path because it feels obviously convenient** — that convenience is the defect. If it genuinely
blocks a real workflow, that is a finding worth reporting, not a thing to fix quietly.

Write `evidence/0004-E02-T02.md`, including what authoring in the app cannot yet do that
authoring in a file could.
