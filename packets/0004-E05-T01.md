## Context

The tracker is live and was put there entirely by hand — local `tofu apply` against local
state, a frontend built on a laptop and pushed through the Hosting REST API by a throwaway
script, and an image digest pasted into a `-var` flag. None of it is repeatable and none of
it links a running revision to a reviewed commit.

`identity-and-tenancy` already solved the equivalent problem for publishing. Read
`.github/workflows/publish-exports.yml` in that repository before designing anything here:
it exchanges a GitHub OIDC token for a cloud role, holds no secret, and is trusted for
exactly one immutable subject on `refs/heads/main`. **Follow that shape.** The cloud is
different; the pattern is not.

**Two facts that will not be obvious from the code.**

A `GITHUB_TOKEN` push raises no workflow events, so a deploy triggered by `push: [main]`
will silently never run behind auto-merge. That repository solves it with a post-merge
`workflow_dispatch`; `scripts/post-merge-workflows.sh` in this one already exists for the
same reason. Use it rather than rediscovering the failure.

The Hosting REST API and `firebase.json` are **different schemas**. Terraform emits the
CLI shape (`source`, headers as a list of `{key,value}`); the REST `ServingConfig` wants
`glob` and headers as a map, and rejects `pinTag`. A translation already had to be written
by hand once. Either use the Firebase CLI, or put the translation in the repository with a
test — do not leave it in a script nobody can find.

## Goal

A merge to `main` deploys the product, keylessly, and the running revision names the
commit that produced it.

## Boundary

**No long-lived cloud credential, anywhere, ever.** No service-account key file, no secret
in Actions, no credential in the repository. If the design appears to need one, stop and
say so — that is a finding, not an obstacle to route around.

**You do not apply the trust policy.** Workload-identity federation between GitHub and GCP
is reserved to the Founder ([ADR-0021](../../../docs/decisions/0021-chief-of-staff-autonomy.md)).
Author it, make the plan reviewable, and stop. Say plainly in your evidence what the
Founder must apply and what it grants.

Do not widen the deploy's permissions to make a step convenient. Do not change the
authority-export contract. Do not touch `packets/`.

## Done when

- **Terraform state is remote, versioned, and lockable.** The migration from the existing
  local state is performed without losing the currently-running infrastructure, and the
  evidence shows the state file's new location and that a second checkout can plan against
  it.
- **The deploy runs on merge to `main` and holds no secret.** `permissions:` names
  `id-token: write` and `contents: read`; the workflow contains no `secrets.` reference and
  no key material.
- **Trust is bound to one immutable subject.** The GitHub principal is matched exactly —
  repository id and `refs/heads/main` — with no wildcard, no prefix, no `pull_request`.
- **One merge produces one deployed revision.** The image is built from the merge commit,
  the stack applied with that exact digest, and the frontend released — in that order,
  each step failing the deploy if it fails.
- **Provenance is checkable from outside.** The running Cloud Run revision and the
  released Hosting version each carry the merge commit, and the evidence shows a command
  that reads it back from the live service.
- **The deploy fails closed.** A non-zero cost guard, a plan that would destroy, or an
  unverifiable authority export stops the deploy. Show each refusing, not just passing.
- **The image is never rebuilt for deploy.** The digest deployed is the digest built and
  scanned, carried forward — not a tag re-resolved later.

## Check

```bash
# no secret material anywhere in the deploy path
! grep -rE 'secrets\.|BEGIN [A-Z ]*PRIVATE KEY|service_account.*\.json' .github/workflows/

# trust is exact, not a pattern
scripts/check-workflow-permissions.sh
GOWORK=off go test ./... -count=1

# and, after a real merge, the live service names the merge commit
gcloud run services describe tracker-reader --region=us-central1 \
  --format='value(spec.template.metadata.annotations)' | grep "$(git rev-parse HEAD)"
```

The last command is the packet. Everything before it is preparation. If it cannot be run
because the Founder has not yet applied the trust, say so and stop with `blocked` — do not
declare the packet done on a plan alone.
