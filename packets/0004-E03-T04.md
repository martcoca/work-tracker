## Context

`0004-E03-T01` blocked on its first attempt, correctly: it must verify something a session
presents, and nothing specified what. `0000-E04-T04` defined the session principal as an
authority *record* — `kind: session`, a packet id, an attempt id, an expiry — and
deliberately left the presented credential out, because
[ADR-0055](../../../docs/decisions/0055-a-worker-reads-in-the-open-and-writes-as-a-session.md)
assumed a cloud-signed token. That assumption failed twice: the chief-of-staff's permission
boundary refuses minting, and the approach welded a portfolio-wide capability to one cloud.

[ADR-0056](../../../docs/decisions/0056-machine-access-is-a-product-feature.md) replaces it.
The tracker issues its own machine credentials, the way every product with machine clients
does. This packet is that feature.

**Authentication and authorization stay separate.** The tracker answers *who is this*.
`0000` answers *what may they do*, through the published grant and the scope vocabulary
`packet:comment` and `packet:transition-status`. Do not put scopes in the credential; a
credential that carries its own permissions cannot be narrowed after issue.

## Goal

A machine client can be issued a credential by the product, present it, and be resolved to a
principal — with the credential listable, revocable, and visibly used.

## Boundary

**Do not implement the write operations.** Comment and status transition are `E03-T01`.
This packet ends at "the request is authenticated as this principal."

**Never store the secret.** Hash it, show it once at creation, and make the hash
irreversible. If any code path can recover a secret from storage, the design is wrong.

**Do not invent a second authority.** The credential proves identity. Whether that identity
may act comes from `0000`'s grant, checked at request time against the held export.

**No credential in a log, an error, or an export.** The packet export is public.

**Do not build a bootstrap that mints without a human.** The first credential is created by
a signed-in human, as in every product with this feature. An agent minting its own authority
is the thing this replaces.

## Done when

- A signed-in human can create an agent credential, and the secret is shown **once** and
  never again — proven by fetching it back and finding only metadata.
- The stored form is a hash. Show that the stored value cannot authenticate.
- Presenting a valid credential resolves to a principal; the request then carries that
  identity and nothing more.
- **Every refusal is distinguishable**: unknown credential, revoked credential, expired
  credential, malformed header. A client must be able to tell "who are you" from "not any
  more" — and each must fail a test that passes with the rule removed.
- Revocation takes effect **immediately**, not at the next export refresh. Show a credential
  working, being revoked, and failing on the next request.
- The credential records when it was last used, so an unused or stolen one is visible.
- **A credential grants nothing by itself.** A valid credential whose principal holds no
  grant in the published export is authenticated and refused. This is the clause that keeps
  authentication and authorization apart; show it.
- Nothing about this reaches the packet export.
