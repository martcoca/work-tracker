## Context

Cloud spend is nearly zero and always was. The real cost of this organization is the
capacity it spends thinking, and nothing records it.

Two components, and they behave differently:

**Actions minutes** are metered on private repositories and free on public ones. The
portfolio is mostly public, so most CI is free — but `identity-and-tenancy` is private by
[ADR-0016](../../../docs/decisions/0016-github-organization-topology.md), and its minutes
are billed. On 2026-09-02 a single mutation run reached **4h19m**, roughly 13% of a month's
allowance, and was found by a human noticing a stalled pull request rather than by any
measurement. Every job is now capped at 30 minutes, which bounds the damage and measures
nothing.

**Model capacity** is the larger cost and the harder one. There is no invoice to read per
dispatch. What is knowable is what was spent on: which packet, which runtime, which
profile, how long the attempt ran, and whether it succeeded. That is enough to answer "what
did this initiative cost to build" without pretending to a precision nobody has.

## Goal

The Founder can see what running the organization cost, per repository and per dispatch,
without opening a billing console or reading a transcript.

## Boundary

**Do not invent a token count you cannot observe.** If the runtime does not report usage,
record what it does report — duration, runtime, profile, outcome — and say plainly that
spend is inferred from those rather than measured. A confident fabricated number is worse
than an honest gap.

**Do not read a transcript to estimate cost.** Transcripts hold credentials-adjacent
context and are not an accounting source.

**Do not add a per-dispatch cloud resource.** This is reporting over facts the
organization already produces.

## Done when

- Actions minutes are reported **per repository, with private and public separated**,
  because only one of them is metered and a combined figure would mislead.
- The report names the most expensive workflow, since that is the actionable fact — the
  4h19m job would have been visible the day it ran.
- A dispatch is recorded with its packet id, runtime, profile, duration and outcome, and
  the record survives the session that made it.
- The report states, in one line, what it does not know. Model spend is inferred; say so.
- **A deliberately expensive run is shown being noticed**, so the report is demonstrated
  to surface a problem rather than merely to exist.

## Check

```bash
GOWORK=off go test ./... -count=1
# plus the report, run once, over a real period, showing real per-repository minutes
```
