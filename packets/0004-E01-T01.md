## Context

This product records what an agent was asked to do, what it did, and what changed. This
packet builds the logic underneath all of it: no cloud, no HTTP, no UI, no identity provider.

**The property that carries the whole product** is that a packet's scope is frozen. Goal,
Boundary, Done-when, Check and Context are written once at issue and never edited by anyone —
human or agent. A packet quietly rewritten mid-flight means a session executed something
nobody can afterwards reconstruct, which is the failure this product exists to prevent.

The file-based convention it replaces enforced that in CI, where it has fired in anger. **A
nicer interface must not reintroduce what a shell script prevented.**

Read the [Technical Specification](../technical-spec.md) *Interfaces and data* section for the
field split. It is the authority on which fields are frozen.

## Goal

An append-only event log that models a packet's whole life, and a projection that derives its
current state — with the freeze, the transition rules and supersession all enforced by the
model rather than by convention.

## Boundary

**Logic only.** No HTTP server, no cloud SDK, no Firestore, no Identity Platform, no UI, no
export serialization — that is T02.

Do not build the session API. It needs a grant from 0000, which does not publish one yet.

Do not invent a scope vocabulary. Scopes are opaque strings here.

## Done when

- **Event types** exist for at least: packet issued, taken, commented, status transitioned,
  superseded, closed. Every event carries an id, a timestamp, and the actor.
- **A projection** derives current packet state from the log, and dropping and rebuilding it
  produces an identical result, proven by a test.
- **A packet body cannot be edited.** There is no operation that mutates Goal, Boundary,
  Done-when, Check or Context after issue. Assert it against the model's own API surface, not
  by inspection.
- **Supersession works and is linked in both directions**: the new packet names its parent,
  the parent is closed as superseded, and the original body is unchanged and still readable.
- **Transitions are legal-only**: `not started → in progress → done`, any state → `blocked`,
  `done` terminal. An illegal transition is refused.
- **A `done` transition without evidence is refused.** Evidence is a required field on that
  transition and on no other.
- **Comments append and are attributed.** No operation edits or deletes one.
- **Every packet carries a tenant id**, opaque here; validating it against a directory is T02.
- Concurrent modification is rejected rather than merged — two transitions from the same prior
  state must not silently produce last-writer-wins.
- **Every rule above has a test that fails when the rule is removed**, and the mutation gate
  proves it rather than an assertion counter.

## Check

From the repository root, with no network:

```bash
go test ./...
go vet ./...
```

Then demonstrate, with output in the pull request:

1. Issue a packet, take it, comment, transition to `done` with evidence. **Show the history.**
2. **Attempt to edit the body.** Show there is no API that does it.
3. Supersede a packet. **Show the original body unchanged** and both links present.
4. **Transition to `done` with no evidence.** Show it refused.
5. Attempt `done → in progress`. Show it refused.
6. Drop the projection, rebuild from the log, **show the result is identical**.
7. Two transitions from the same prior state — **show the second is rejected, not merged.**
8. Delete the evidence-required check from the implementation and show the **mutation gate**
   reports a new survivor. Restore it.
