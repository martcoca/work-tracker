## Context

The service was deployed to Cloud Run for the first time and **refused to start**. The log is
exact:

```
agent-grants:     stale export: expired at 2026-08-29T22:26:14.283Z
tenant-directory: stale export: expired at 2026-08-29T22:36:22.867Z
startup refused: no usable export is held: packets is missing: packets: fetch request failed
Container called exit(1).
```

**Two of those three were the system working.** Identity's exports had genuinely expired, and
this service correctly refused to serve on stale authority — a consumer enforcing another
product's freshness bound, in production, unprompted. That behaviour stays exactly as it is.

**The third is a deadlock.** `packet_export_url` defaults to
`https://tracker.martcoca.com/packets.json` — an export *this service publishes*. It cannot
start without its own output, and its own output cannot exist until it starts.

T04's rule was right for authority and wrong for this: *"Startup with no reachable export and
nothing held is a refusal, not an empty page."* The distinction it is missing is **whose
export it is.**

## Goal

The service starts with no packet export of its own, and still refuses to start without the
authority exports it does not own.

## Boundary

**Do not weaken the authority rule.** A missing or stale `tenant-directory` or `agent-grants`
must still refuse startup and must still fail closed at runtime when what is held expires.
That behaviour has now been demonstrated in production and is the product's central claim.

Do not add a bypass flag, an environment escape, or a "development mode" that skips
verification. A switch that makes the strict path optional will be found and used.

Do not change the export contract, the fetch mechanism, or the refresh timing.

## Done when

- **A missing packet export is a startable state.** The service starts, serves, and reports
  that it holds no packets — which is a true statement about an empty tracker, not an error.
- **A packet export that is present but invalid is still a refusal.** Malformed, wrong
  digest, or expired is a broken publisher, not an empty one, and must not be treated as the
  same thing.
- **Authority exports are unchanged.** Missing, stale, tampered or unreachable
  `tenant-directory` or `agent-grants` still refuses startup, and still fails closed at
  runtime when a held copy expires.
- **The distinction is explicit in the code**, not implied by ordering — a reader should be
  able to see which exports are required and which are the service's own.
- **The empty state is visible to a human.** A tracker holding no packets says so; it does
  not render as though it has none because something failed.
- Every rule above has a test that fails when the rule is removed.

## Check

```bash
go test ./... && go vet ./...
```

Then demonstrate, with output in the pull request:

1. **Start with no packet export reachable**, authority exports valid. Show it starts, serves,
   and states that it holds no packets.
2. **Start with a malformed packet export.** Show it refuses — the difference between absent
   and broken.
3. **Start with authority missing.** Show it still refuses.
4. **Start with authority stale.** Show it still refuses, naming staleness.
5. **Publish a packet export while running**, and show it picked up on the next refresh
   without a restart.

## Notes

The failure this fixes was found by deploying, not by testing. Every test used fixtures that
were present, because the packet that wrote them asked for exports that exist. **The absent
case was never exercised**, and the first real deployment found it in ninety seconds.

Worth carrying into the evidence: which other inputs this service treats as required, and
whether each is genuinely required or merely always-present-so-far.
