## Context

The authoring surface exists and writes to memory. Cloud Run scales to zero, so an authored
packet lives until the instance recycles. The tests pass because the model is in memory and
that is where they exercise it.

**The event model is append-only** (`0004-E01-T01`): a packet's state is a projection over
its events, and dropping and rebuilding the projection must produce an identical result.
A store that overwrites a row loses that property silently. Preserve the log, not the
projection.

**Cost is the gate, and it is a real one.** The shared denylist in `cost-guard` refuses
resource types that charge whether or not anybody uses them — compute instances, forwarding
rules, NAT, GKE, Cloud SQL. Firestore is not among them because it has a genuine free tier.
The tracker's **own** allowlist in `internal/costguard` is stricter and lists types
explicitly; whatever store you choose must be added there **deliberately, with the reason
stated in the diff**, not slipped in to make a plan pass.

Read `doctrine/shared/cloud.md` first. Its rule — state what a thing costs and whether it is
in a free tier — is the one this packet is gated on.

## Goal

What the app is told survives the container that was told it.

## Boundary

**No always-on resource.** If the store requires a provisioned instance, a minimum node, or
a warm replica, it is the wrong store. Stop and say so rather than reaching for the guard's
allowlist.

**Do not change the packet model.** This packet gives the existing model somewhere to live.
If persisting it appears to require changing transition rules, the freeze, or supersession,
that is a finding — report it and stop.

**Do not build the session API.** Writes still arrive only from the human surface. Identity
for sessions is `0004-E03-T01` and ADR-0055.

**Do not migrate `packets/` into the store.** T02 inverts the export; migration is E04.

## Done when

- Packet state is durable across a **cold start**, proven by authoring a packet, forcing a
  new instance, and finding it intact — not by a unit test against a fake.
- **The append-only property survives the store.** Dropping the projection and rebuilding it
  from persisted events produces an identical result, proven by a test that does exactly
  that against the real store.
- **Two concurrent writers cannot lose an event.** Show the losing writer being refused or
  retried, not silently overwritten. A store that makes an append-only log last-write-wins
  has broken the model while passing every other check.
- The resource type is added to `internal/costguard`'s allowlist **in the same change**,
  with the reason in the diff, and the plan passes the guard with idle cost zero.
- Startup still fails closed when authority exports cannot be verified. Adding a store must
  not create a second path that boots without authority.
- The evidence states what the store costs at rest and at the expected volume, in figures.

