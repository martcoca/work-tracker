## Context

T01 built the model. This packet makes it **readable by a session that never calls this
product** — which is the constraint the whole architecture rests on.

If a session had to call the tracker to learn what work it has, every session in the
organization would acquire a synchronous dependency on one service. That is the shared spine
[ADR-0005](../../../docs/decisions/0005-range-is-the-deliverable.md) rejects, and it would
mean this product being down stops all work everywhere.

**So a session reads a file.** The envelope is deliberately the same one
[0000](../../0000-identity-and-tenancy/technical-spec.md) publishes — one envelope shape
across the portfolio is worth more than a bespoke one here, and 0000's is already proven.

This packet also introduces the **other** direction of the 0000 relationship: validating a
packet's tenant against 0000's published tenant directory, read as a file.

## Goal

Packets serialize to a versioned, digest-verifiable export with a one-hour freshness bound,
and a packet naming an unknown or retired tenant is refused at issue.

## Boundary

**Serialization and validation only.** No HTTP, no cloud upload, no publishing to object
storage — writing to a local directory is the whole scope.

**Do not fetch anything.** 0000's tenant directory is an input you are handed as a file. A
network call here would defeat the packet's own purpose.

Do not build the session API or the human surface.

## Done when

- Packets serialize with the shared envelope: `schema`, `published_at`, `expires_at`,
  `source`, `digest`, `payload`. Schema name `martcoca.tracker.packets/1`.
- **`expires_at` is exactly one hour after `published_at`**, asserted by a test. The same
  bound as 0000, because two different bounds in one organization is a footgun.
- **The digest is stable**: the same logical state serializes to the same digest regardless of
  insertion or key order.
- **A verifier refuses a stale export and refuses a tampered payload**, distinguishably from
  each other and from "not found".
- **A packet naming a tenant absent from the supplied directory is refused at issue.**
- **A packet naming a `retired` tenant is refused differently** from one naming an unknown
  tenant. Absence and denial must not look alike.
- Provenance is real or the publisher fails — no placeholder repository or commit.
- Every rule has a test that fails when the rule is removed, proven by mutation.

## Check

```bash
go test ./...
go vet ./...
```

Then demonstrate:

1. Serialize a set of packets. **Show the envelope.**
2. **Show `expires_at` minus `published_at` is exactly one hour.**
3. Serialize the same state twice with different insertion order. **Show identical digests.**
4. **Change one byte of the payload.** Show the verifier rejects it on the digest.
5. Verify a freshly published export at a simulated time past `expires_at`. **Show it refused
   as stale**, and that this is a different failure from the tampered case.
6. Issue a packet naming an unknown tenant → **refused**. A retired tenant → **refused
   differently**. Show both messages.
