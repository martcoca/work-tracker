## Context

`0004-E02-T03` was blocked, correctly, and the reason was a defect in the specification
rather than in the repository. The Cloud Run configuration points the service at
`/data/packets.json` and `/data/tenant-directory.json`, and **nothing puts files there.**

The specification said "reads a file" throughout and never said how the file arrives. Both
obvious answers are wrong:

- **Baking exports into the image** ships authority frozen at build time, under a one-hour
  freshness bound. It is stale the moment the artifact is built.
- **A binary with nothing at those paths** starts and fails.

**The Technical Specification now decides this**: a reader fetches over HTTPS and holds the
last good copy. Read its *How a reader actually obtains an export* section — it is the
authority on the behaviour below.

This packet builds that, and it must exist before an image is worth building. It is entirely
offline to develop and test: the thing being fetched is a static file, and a fixture served
from disk or a local stub proves every rule here.

## Goal

The service obtains its exports at runtime, verifies them, keeps serving when a fetch fails,
and fails closed when what it holds expires.

## Boundary

**No image, no Dockerfile, no registry.** That is T03, and it becomes straightforward once
this exists.

**No cloud, no deployment, no credential.** The exports are public static objects; fetching
one needs no authentication. If a fetch appears to need a credential, stop — that is a
finding about the export being in the wrong place, not something to solve with a secret.

Do not change the export contract, the packet model, or the surface's route inventory.

**Do not make the fetch a request-path dependency.** A page load must never block on an
outbound HTTP call, and a user must never see a slow page because a CDN was slow.

## Done when

- **On start and on a schedule**, the service fetches each export it depends on: this
  product's packet export, and 0000's `tenant-directory` and `agent-grants`.
- **Each fetched copy is verified on arrival** — digest against payload, and `expires_at`.
  A copy failing either is **refused and the previous good copy is kept**.
- **A failed fetch is not an outage.** With the network unavailable, the service continues
  serving from the last good copy, and the copy's age is visible.
- **When a held copy passes `expires_at`, the reader fails closed** on whatever that export
  authorises. It does not serve stale authority and does not extend the bound.
- **Startup with no reachable export and nothing held is a refusal, not an empty page.** A
  service that starts and silently shows nothing is indistinguishable from one showing that
  there is nothing.
- **The fetch never blocks a request.** Prove it: a page renders while a fetch is hanging.
- Endpoints and the schedule are configuration, not constants, with sane defaults.
- Every rule above has a test that fails when the rule is removed.

## Check

From the repository root, with no network:

```bash
go test ./... && go vet ./...
```

Then demonstrate, with output in the pull request:

1. **Start against a local fixture export.** Show it fetched, verified, and served.
2. **Serve a tampered copy.** Show it refused on the digest and the previous copy retained.
3. **Kill the source, then request a page.** Show it still served from the held copy, with
   the age visible.
4. **Advance past `expires_at`.** Show it failing closed on what that export authorises, and
   that the failure names staleness.
5. **Start with nothing reachable and nothing held.** Show a refusal rather than an empty
   page.
6. **Hang the fetch and load a page.** Show the page renders and does not wait.

## Notes

The real endpoints exist today and are public:
`https://identity.martcoca.com/tenant-directory.json` and `.../agent-grants.json`. **You may
fetch them in a demonstration** — they are static public objects and need no credential. Do
not depend on their content in a test: a test that breaks when a real tenant is added is a
test of the wrong thing.

The one-hour bound is the same number 0000 uses, deliberately. Two different bounds in one
organization is a footgun.

Write `evidence/0004-E02-T04.md`, including exactly what T03 must place in the image and what
it must not — that list is what unblocks the packet this one was carved out of.
