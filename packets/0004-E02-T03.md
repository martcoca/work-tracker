## Context

clean plan, correctly. Its output says plainly what it did not create:

```

```

`container_image` is a **required variable** with no default, and **nothing in this
repository produces one.** The Go service exists — E01 landed the packet model, the export
contract and the tenant reader — but there is no Dockerfile, no build, and no registry push.

So the apply cannot happen, the Firebase site cannot exist, the custom domain cannot be
added, and no DNS records can be issued. **This packet is the whole cloud path's blocker**,
and it is entirely offline work with no approval attached.

That gap is the packet author's, not the previous session's: the arc was written as
"author infrastructure, stop at a plan" and never included the artifact the plan consumes.

## Goal

A reproducible container image is built from this repository, runs the service, and is
published to a registry Cloud Run can pull from — with the image reference recorded so the
apply has something real to point at.

## Boundary

**No apply, no provisioning, no GCP resource created.** Building and pushing an image is
not provisioning; applying the plan is, and it stays with the Founder.

**Do not change the service's behaviour.** This packet makes what exists deployable. If the
service needs a change to run in a container — a port from the environment, a health
endpoint — that is in scope and must be called out; anything beyond it is not.

**No credential in the image, in a layer, or in the repository.** Not a token, not a service
account key, not a `.env`. The image is public-shaped even if the registry is not.

Do not build the read surface into the same image unless E02-T01's configuration expects
that. Read its outputs and match what the plan already assumes.

## Done when

- A `Dockerfile` builds the Go service reproducibly from a pinned base image — **by digest,
  not by tag.** A tag is mutable and a rebuilt "same" image is not the same image.
- **The build is multi-stage** and the final layer contains no compiler, no module cache and
  no source. State the final image size.
- **It runs as a non-root user** and listens on the port Cloud Run supplies via `$PORT`,
  defaulting sensibly when unset.
- **A container health check succeeds** against the running image locally, before any cloud
  is involved.
- **The image is published** to Artifact Registry, and the **immutable digest** is recorded —
  `...@sha256:...`, never a floating tag. The plan pins the digest.
- **CI builds the image on every pull request** and pushes only on merge to `main`, keyless
  through the federation `platform-gcp` provides. **No stored credential.**
- **The image contains no credential**, asserted mechanically — scan the built layers rather
  than reading the Dockerfile.
- Every rule above has a test or a CI assertion that fails when the rule is removed.

## Check

From the repository root:

```bash
go test ./... && go vet ./...
docker build -t work-tracker:check .
docker run --rm -e PORT=8080 -p 8080:8080 -d --name wt-check work-tracker:check
curl -fsS http://localhost:8080/healthz     # or whatever the service exposes
docker rm -f wt-check
```

Then demonstrate, with output in the pull request:

1. **The build**, and the final image size.
2. **The container serving** a real request locally — not a claim that it would.
3. **`docker run` as a non-root user**, shown by `id` inside the container.
4. **The published digest**, in full.
5. **The credential scan** over the built layers, and the scan **failing** when you add a
   dummy secret file to the image. Remove it.
6. **The base image pinned by digest** in the Dockerfile, and a statement of which base and
   why.

## Notes

Cloud Run requires the container to listen on `$PORT` and to start within its timeout. A
service that binds a hardcoded port works locally and fails on deploy with an opaque
"container failed to start" — that is the most common way this packet's output breaks at
apply, and the Check above is written to catch it before the Founder does.

If Artifact Registry does not exist in the project yet, **stop and say so** rather than
creating it: that is provisioning and it is not yours. Say exactly what is needed.

If pushing to a registry needs a credential you do not hold, stop and record a `blocked`
issue naming what is missing. Do not vendor a key.

Write `evidence/0004-E02-T03.md`, including the digest and everything the Founder needs to
apply — this is the packet whose output the apply directly consumes, so its evidence is the
handover.
