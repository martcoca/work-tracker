- **Status:** not started
- **Source:** initiatives/0004-agentic-work-tracker/E05-continuous-delivery/T03-publish-the-packet-export.md

## Context

The tracker is deployed, authenticating, and **empty**.

`packetexport.Publish` exists, is tested, and is called by nothing. `deploy.yml` *verifies*
`https://tracker.martcoca.com/packets.json` before every deploy, and no step has ever
produced that file. The reader is built to tolerate its absence — `0004-E02-T05` made
startup survive it deliberately — so the service comes up healthy and shows a reader
nothing at all.

That absence is also why the service went down on 2026-09-02: with no file present, the
Hosting single-page rewrite answered the fetch with `index.html`, and an export that is
HTML rather than JSON is not absence. The gap is now handled safely. It is still a gap.

**The source of packet truth today is `packets/` in each repository**, which
[E04](../E04-migration/epic.md) exists to retire. This packet does not retire anything. It
publishes what already exists so the app has something real to show, and so E04 has a
working export to migrate onto rather than a design.

## Goal

`https://tracker.martcoca.com/packets.json` is a real, verifiable export of this
repository's packets, republished by the deploy, and the signed-in app renders it.

## Boundary

**Do not change the packet model, the export contract, or `FreshnessBound`.** This packet
publishes an existing format; it does not negotiate one. If the contract seems to need a
change, that is a finding — say so and stop.

**Do not migrate other repositories' packets.** That is E04, it is gated on a session
having executed a packet delivered only as an export, and doing it early would make the
app authoritative for records it cannot yet write.

**Do not invent a write path.** Comments and status transitions are `0004-E03-T01`.

**The export must be produced by the product's own code.** Call `packetexport.Publish`.
A hand-assembled JSON file with a hand-computed digest is not an export, it is a fixture
that happens to parse.

## Done when

- A command in `cmd/` builds the export from `packets/` and writes it, with provenance
  naming the commit it was built from.
- The deploy publishes it to Hosting **before** the step that verifies runtime authority,
  so a deploy cannot succeed while leaving the app unreadable.
- `curl https://tracker.martcoca.com/packets.json` returns a valid envelope whose digest
  verifies and whose `expires_at` is `contract.FreshnessBound` after `published_at`.
- **`verify-runtime-exports` passes against the live file**, not a fixture.
- The export is republished on every deploy, so it can never be staler than the last
  merge plus the scheduled identity publish. State plainly in evidence what happens if
  `main` is quiet for longer than `FreshnessBound` — that is a real consequence of
  ADR-0053 and this packet inherits it.
- **A signed-in reader sees the packets**, shown by an authenticated request against the
  live service returning them — not by a screenshot and not by a local run.
- Every packet in the export carries its real status, and a `superseded` packet is
  distinguishable from a `done` one.

## Check

```bash
GOWORK=off go test ./... -count=1
curl -sf https://tracker.martcoca.com/packets.json | head -c 200
GOWORK=off go run ./cmd/verify-runtime-exports    # against the live URLs
```

## Evidence

Write `evidence/0004-E05-T03.md` with the live `curl` output, the verifier's result
against the live file, and the authenticated request showing packets rendered. If the
signed-in check cannot be performed because sign-in is not usable, stop with `blocked`
and say exactly what is missing rather than declaring the packet done on the export alone.
