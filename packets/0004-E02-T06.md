# T06: Issue an agent credential in the app

- **Initiative:** 0004 — Agentic Work Tracker
- **Epic:** E02 — the human surface
- **Packet id:** `0004-E02-T06`
- **Executor:** `worker`
- **Target:** The `work-tracker` repository
- **Approval:** none
- **Shape:** `execution`
- **Status:** not started
- **Source:** initiatives/0004-agentic-work-tracker/E02-the-human-surface/T06-issue-a-credential-in-the-app.md

## Context

[ADR-0056](../../../docs/decisions/0056-machine-access-is-a-product-feature.md) made machine
access a product feature. `0004-E03-T04` built the routes —
`POST /api/agent-credentials`, list, detail, revoke — and `0004-E03-T05` gave each credential
the workload it acts as. Every one of them sits behind the Identity Platform verifier, so
only a signed-in human can call them.

**Nothing human-facing calls them.** `web/` contains zero references to `agent-credentials`.
So "a signed-in human can create an agent credential" is true of the API and false of the
product: the only way to create one today is to lift an ID token out of a browser session
and call the API by hand, which is the borrowed-authority manoeuvre the doctrine exists to
prevent.

That is a decomposition defect, not a worker error. `E03-T04`'s clause was satisfiable at the
API level and was correctly closed there; no packet ever owned the surface. This one does.

It is also the step everything else waits on. `0004-E03-T01` must present a real credential
against the deployed service, and ADR-0056 is explicit that no agent mints its own authority
— the first credential is created by a signed-in human. Until that human has a door, the
chain stops here.

## Goal

A signed-in human creates, sees once, lists and revokes an agent credential without leaving
the app.

## Boundary

**Do not change the credential routes or their rules.** `0004-E03-T04` and `0004-E03-T05`
own them. If a route is missing something this surface needs, report it rather than widening
it here.

**No session API and no agent write-back.** This is the human surface, per the epic.

**The secret is shown once, in the browser, and never again.** Do not persist it to
`localStorage`, `sessionStorage`, a cookie, the URL, or application state that survives a
navigation. Do not log it. A reload must not recover it — the server keeps only a digest, and
the interface must not quietly become the place a secret lives.

**No tenant administration.** One tenant exists.

## Done when

- A signed-in human can create a credential, naming the packet, the attempt, and the
  **workload** it acts as (issuer and subject), and choosing an expiry within the permitted
  maximum.
- **The secret appears exactly once**, plainly marked as the only time it will be shown, with
  a copy affordance. Reloading or navigating away and back shows metadata only. A test proves
  the value is unrecoverable after the first render.
- Listing shows each credential's id, workload, packet, attempt, creation, expiry, last use,
  and revoked state. **A revoked credential is shown as revoked, never removed** — absence
  and denial must not look alike.
- Revoking works from the surface and the row updates without a reload.
- **Every refusal the routes make is surfaced distinguishably**, in words a human can act on:
  a workload tenant that is not theirs (`403 workload_tenant_mismatch`), a malformed or
  absent issuer or subject (`422 invalid_workload`), and an expiry beyond the maximum.
- The surface meets the same accessibility bar as the rest of the app, verified by the
  existing suite rather than by inspection.
- Every rule above has a test that fails when the rule is removed. Show the failures.
