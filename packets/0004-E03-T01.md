## Context

**This is where two initiatives meet.** A session authenticates with a credential this
product issued, acting as a **workload** that holds a grant issued by
[0000](../../0000-identity-and-tenancy/technical-spec.md), and writes back comments and
status.

When it works, it is also the first demonstration of **0000's** acceptance scenarios 2 and 4 —
a grant honored by a product that never calls the one that issued it. Both initiatives have
recorded those as unschedulable for want of a second consumer. This is that consumer.

**Prerequisite:** 0000 must be publishing a grant for the **workload** your credential acts
as. `0000-E04-T05` issued the first grant and the export is no longer empty, but
[ADR-0057](../../../docs/decisions/0057-the-session-is-not-an-authority-record.md) supersedes
that grant: it names the work-tracker *repository* subject, and nothing presents a GitHub
Actions token when an agent comments on a packet. Its replacement names this product's Cloud
Run runtime identity. Authoring it is the chief-of-staff's, not yours.

If no grant exists for your workload, that is the correct blocked state — **and the packet is
still satisfiable**, because "a valid credential holding no grant is authenticated and
refused" is one of the rules you must prove.

**Do not reimplement 0000's rules from its source.** A second divergent copy of validation
logic is exactly what initiative 0010 spent five packets removing from this portfolio. The
agreement mechanism across the language boundary is `0000-E05-T04`'s conformance vectors:
pass them, and a drift on either side turns a build red rather than a service wrong.

**Authentication is `0004-E03-T04`, not this packet.** It issues and resolves the credential.
This packet starts from an authenticated principal and decides what it may do.

## Goal

A session with a live grant can read its packet, comment, and transition status — denied by
default, and denied entirely for anything its grant does not name.

## Boundary

**No new identity mechanism, and no credential stored here ever.** If this packet seems to
need a secret, the design is wrong — stop.

**No route edits a packet body**, for any actor. The session API has three operations and
none of them is edit.

Do not build revocation timing — that is T02. Do not migrate `packets/`.

Do not define a scope vocabulary alone. It must be agreed with 0000, which has deliberately
left it open awaiting a second consumer. **Propose it; do not unilaterally name it.**

## Done when

- A session authenticates presenting **an agent credential this product issued**
  (`0004-E03-T04`), which resolves to exactly one principal. The credential carries the
  packet and attempt it is bound to, and **the workload it acts as**; the grant lookup uses
  the workload's issuer and subject, and never the attempt
  ([ADR-0057](../../../docs/decisions/0057-the-session-is-not-an-authority-record.md)).
  No cloud mints anything — [ADR-0056](../../../docs/decisions/0056-machine-access-is-a-product-feature.md)
  replaced that mechanism after it proved unbuildable.
- **The packet binding is enforced here, not by 0000.** A credential bound to packet P is
  refused on any other packet, distinguishably, because this product minted that binding and
  `0000` never sees it.
- **0000's rules are honoured through its published conformance vectors** (`0000-E05-T04`),
  not reimplemented from reading its source. The validator is TypeScript and this product is
  Go, so "consume it as a dependency" was never possible; the vectors are how the two agree.
- `GET` a packet, `POST` a comment, `POST` a status transition — all three requiring a live
  grant and a recognized scope.
- **Deny by default.** An unknown credential, a revoked credential, an expired grant, an
  unrecognized scope, and a malformed request each deny, **distinguishably**. A caller must
  be able to tell "who are you" from "not any more" from "not yours".
- **A session cannot reach a packet outside its tenant.**
- **A `done` transition without evidence is refused over the API**, as it is in the model.
- Comments are appended and attributed to the principal, never overwritten.
- Transitions carry a caller-supplied idempotency key, and a repeat is a no-op rather than a
  duplicate event.
- Every rule has a test that fails when the rule is removed.

### The live clauses `0004-E03-T04` could not reach

`E03-T04` built credential issuance and correctly stopped at "the request is authenticated
as this principal" — it was forbidden from building a route on which a credential could be
presented. That left its live behaviour unobservable against the deployed product, because
until this packet ships there is nothing to present a credential *to*. That was a
decomposition error, not a worker error, and these clauses land here because this is the
packet that makes them provable:

- Against the **deployed** service, a real packet-bound credential authenticates, and
  `last_used_at` advances as a result.
- Against the deployed service, the four machine refusals stay distinguishable: malformed
  header, unknown credential, revoked credential, expired credential.
- A credential revoked while live stops working on the **next** request, not at the next
  export refresh.
- A credential whose principal holds no grant in the published export is authenticated and
  refused, live.

**Do not use the Founder's signed-in browser to create the credential.** An agent acting
through someone else's authenticated session is exercising their authority. Creating the
first credential is a human action; ask for it, and have the bearer handed over through a
channel that never puts it in a transcript.

## Check

```bash
go test ./... && go vet ./...
```

Then demonstrate:

1. A session with a live grant: **read, comment, transition.** Show the history.
2. **A scope the grant does not name** → denied, with its own error.
3. **A subject in the mutable claim form** → denied.
4. **A packet in another tenant** → denied, distinguishably from not-found.
5. **`done` with no evidence** → denied.
6. **The same transition twice with one idempotency key** → one event.
7. Show the validator is imported from 0000 rather than reimplemented.

## Notes

**Never print a token.** Not in output, not in evidence, not redacted-but-present. Test for
presence, never value.

If 0000's grant contract turns out to be awkward for this consumer, **that is the most
valuable finding this packet can produce** — it is the first time anything has consumed it,
and 0000 can still change. Report it rather than working around it.
