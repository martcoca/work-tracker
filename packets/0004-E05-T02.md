## Context

`tracker.martcoca.com` was brought up by hand: the Firebase custom domain registered
through a REST call, the CNAME and ACME TXT record added manually in Cloudflare. The stack
records this honestly — `apply_prerequisites` reports
`dns_and_certificate_managed = false` — but a fact that is true only because someone
remembers doing it is not managed.

Rollback is in the same state. Hosting keeps every released version and Cloud Run keeps
every revision, so rolling back is *possible*; it is simply undocumented and, today,
reachable only from the chief-of-staff's laptop.

**T01 comes first.** This packet assumes a deploy pipeline exists and state is remote.

## Goal

The domain is managed by the plan or explicitly disclaimed with a reason, and any
deployed version can be rolled back by one action from CI.

## Boundary

**Do not move DNS hosting.** The zone lives at the registrar the Founder controls; this
packet may read it and may document required records, but does not migrate it and does not
store an API token for it in this repository.

If managing the certificate in the plan would require holding a DNS credential, **do not
do it** — record why, keep the disclaimer honest, and make the manual step precise instead.
A truthful `dns_and_certificate_managed = false` beats a credential nobody wanted.

## Done when

- The custom domain and certificate are either created by the plan, or the plan's
  `apply_prerequisites` names them with the exact records required and the reason they are
  human-owned. No third state.
- A rollback of the frontend to a previous Hosting release is one CI action, documented,
  and exercised at least once.
- A rollback of the API to a previous Cloud Run revision is one CI action, documented,
  and exercised at least once.
- Rolling the frontend back does not silently leave it talking to a newer API than it was
  built against — either the two roll together, or the incompatibility is detected and
  refused.
- The evidence shows both rollbacks actually performed against the live product and then
  rolled forward again.

## Check

```bash
tofu -chdir=infra/identity plan -detailed-exitcode   # 0 or 2, never 1
curl -sf https://tracker.martcoca.com/ >/dev/null    # domain serving over TLS
```

Plus the two rollbacks, performed and shown in evidence. A documented rollback that has
never been run is not a rollback — it is a paragraph.
